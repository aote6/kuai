# Kuai 设计原则

从真实 bug 中提炼，每次踩坑后更新。

---

## 1. 最小修改原则

块只应修改它必须修改的字段。不要"顺手"重新推断本可以透传的字段。

**反例**：`move_block` 曾根据 `os.path.isdir()` 重新计算「对象类型」，导致移动压缩包后类型被错误改写为"文件"。

**正确做法**：移动/复制/重命名只碰「当前对象」（位置），不碰「对象类型」（语义），因为这些操作不改变对象的本质。

**检查方法**：写完一个块后，问自己——"我改了哪些字段？有没有改不该改的？"

---

## 2. 字段所有权原则

State 中的每个字段有且仅有一个"所有者"块。其他块可以读取，但不能写入。

| 字段 | 所有者 | 说明 |
|------|--------|------|
| `当前路径` | `进入` | 只有进入能改变工作目录 |
| `当前对象` | 选取/筛选/压缩/解压/移动/复制/重命名 | 路径可被多个块更新 |
| `对象类型` | 选取/筛选/压缩/解压 | 只有真正改变对象形态的块才能重写 |
| `筛选结果` | `筛选` | 历史查询结果，其他块不得修改 |
| `文件列表` | `列表` | 目录快照，其他块不得修改 |
| `文件内容` | `读取` | 文件内容快照 |

**反例**：`batch_rename` 曾经覆盖 `筛选结果`，污染了筛选块的历史产物。

---

## 3. 幂等性检查

块如果可能被重复执行（定时任务、重试），必须考虑："如果这次操作的结果已经存在，怎么办？"

**反例**：`batch_rename` 曾无条件加前缀，重复执行产生 `backup_backup_x.txt`。

**正确做法**：执行前检查目标状态是否已达成，已达成则跳过，返回 `重命名数量=0`。

**注意**：不是所有块都必须幂等（删除、发送天然不是），但必须在 `.block` 的 `属性:` 段落声明 `幂等: true/false`。

---

## 4. State 必须反映真实世界

块修改了外部世界（移动了文件、改了文件名），必须如实写回 State 对应的字段。

**反例**：`batch_rename` 最初只更新了「重命名数量」，没有更新「当前对象」，导致后续块拿着失效的旧路径。

**验证方法**：执行后 `os.path.exists(state["当前对象"])` 必须为 `True`。

---

## 5. 契约字段的两种类型

- **语义字段**：块运算产生的正式结果，永久保留在 State 中（如 `当前对象`、`对象类型`）
- **参数字段**：以 `_` 开头的内部字段，执行后自动清理（如 `_前缀`、`_扩展名`）

不要在语义字段前加 `_`，不要把参数当输出字段处理。

---

## 6. 路径必须是绝对路径

State 中的所有路径字段必须是绝对路径。相对路径会在块链传递中丢失上下文。

**反例**：如果 `选取` 返回相对路径 `a.txt`，后续 `压缩` 在执行时可能找不到文件。

---

## 7. 新增块的检查清单

写一个新块之前，逐项确认：

- [ ] 这个块会不会改变「对象类型」？如果不会，就不要碰这个字段
- [ ] 这个块重复执行一次，结果会不会变得不对？如果是，声明 `幂等: false`
- [ ] 这个块的输出能不能被现有块直接消费？还是要发明新类型？
- [ ] 块修改了文件系统后，State 有没有同步更新？
- [ ] 所有路径输出是不是绝对路径？
- [ ] `.block` 的输入声明是否包含代码中 `state["..."]` 读取的所有字段？
